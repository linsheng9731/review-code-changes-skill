# Review 判断规则

## 风险优先检查

| 场景 | 必须追踪的证据 | 重点验证 |
|---|---|---|
| 权限/租户 | 入口、身份来源、资源所有权、所有消费者 | 绕过 UI、跨租户 ID、过期身份 |
| 事务/扣费/状态 | 更新顺序、原子条件、唯一键、补偿 | 并发请求、重复回调、部分写入后失败 |
| 长任务/外部模型 | 超时、重试、幂等键、取消、恢复与计费 | 提交成功响应丢失、重启、回调乱序 |
| 资源/流式处理 | task/process/socket 生命周期、关闭与背压 | 断开、异常退出、半关闭、缓冲耗尽 |
| 契约/兼容 | 类型与序列化、旧数据、新旧客户端、共享调用者 | 缺失字段、空值、旧版消费方 |
| 数据/迁移 | 回填、约束、索引、上线顺序、回滚 | 混合版本、迁移中途失败 |
| 性能/并发 | 访问次数、锁范围、复杂度、批量上限 | 大输入、N+1、热路径阻塞 |
| UI/状态 | 请求竞态、loading/error、取消、后端能力映射 | 连续提交、切换对象、迟到响应覆盖 |
| 配置/依赖 | 默认值、环境差异、版本 API、生成来源 | 环境不一致、隐含破坏性升级 |
| 测试修改 | 断言强弱、关键分支、mock 与真实契约 | 删掉行为仍通过、失败路径漏测 |

仅按项目适用项深入；读调用者与约束，不能把表面模式当成证据。

## 必要性取值

| 值 | 使用条件 | 注释必含 |
|---|---|---|
| 必须 | 目标或约束离开该改动无法成立 | 移除后具体哪个行为/契约/验证失败 |
| 可选 | 改善维护、体验或验证但非目标前提 | 保留收益及成本，可单独提交与否 |
| 疑似多余 | 有证据表明重复、无消费者、偏离目标或无益复杂度 | 证据及仍需确认条件，不擅自删除 |
| 待确认 | 缺少需求、运行条件或上下文 | 精确说明缺什么，不强推结论 |

风险与必要性独立：必须改动也可能实现错误，可选改动也可能高风险。

## 证据等级

- 已确认/高置信度：复现或充分代码推导，给具体输入、路径和结果。
- 高度可疑/中置信度：已观察危险实现，但运行条件或契约不足；明确待验证条件。
- 待确认/低置信度：材料缺口，放未决问题，不制造缺陷。
- 既有问题：base 版本证据，单列；若本次扩大影响，描述新增影响。

“可能有竞态”“建议增加测试”“代码复杂”不足以成为缺陷；必须给触发与后果。没有问题时用空态，不写假卡片。

## 把技术结论翻译成具体场景

下面只是写法参考，不能当作发现问题的证据。根据实际代码选择动作、对象和结果，不原样套用。

| 术语 | 可采用的白话解释（需有对应证据） |
|---|---|
| 幂等性不足 | 同一任务被重试或通知两次时，会再次执行/扣费，而没有识别它已经处理过。 |
| 竞态 | 两个请求几乎同时处理同一记录，都读到了旧状态，后完成的请求覆盖了另一个结果。说明具体两个请求和错误结果。 |
| 补偿缺失 | 前面已经扣了额度，后面的生成失败后，少了把额度退回的那一步。 |
| 原子性问题 | 几个必须一起完成的更新只完成了其中一部分，例如余额已扣，任务记录却没保存成功。 |
| 契约不兼容 | 原来调用方等的是一种返回格式，新代码换了格式，但调用方仍按原来的方式读取，因而取不到结果。 |
| 背压问题 | 音频产出的速度比发送速度快，来不及发出的数据不断积在内存里。解释实际上限与影响，不能无证据断言崩溃。 |

先解释问题再保留术语作为补充。白话不能降低准确性：保留特定运行条件、未知前提、影响范围和“已确认/待验证”的区别。系统内部问题用可观察的状态、数据和执行结果解释；没有用户表现证据时不要编造界面提示。
